## 相手について
- プログラミング初心者。説明は平易に、専門用語には一言添える
- 確認の質問は設計が分岐するときだけ。それ以外は合理的な既定値で進め、採用した前提を報告に1行書く
- 回答には作業先・確認先のパスやコマンドを必ず書く

## 進め方
- 新しいモジュールや画面を作る前に、計画を5行以内で書いてから実装する
- コマンドが失敗したら、エラー全文を読んでから直す。推測で直さない
- 「できました」と言う前に必ずテストを実行し、結果を報告に含める
- 区切りごとに git commit する（メッセージは何をしたかが分かる日本語）
- 一区切りついたら code-reviewer サブエージェント（/dev-guard:review）でレビューし、重大／要修正を直してから次へ進む
- 複数段階（S0〜S7 など）の作業は、段階の完了報告を書いたら指示を待たずに次の段階へ進む。止まるのは、設計が分岐して既定値で決められないときと、全段階が完了したときだけ。ユーザーの手作業が必要な確認は docs/pending_checks.md に保留として書き、先へ進む

## コードの書き方
- ファイルの読み書きは必ず encoding="utf-8" を明示する
- パスは pathlib.Path で扱い、文字列連結しない
- 例外は握りつぶさず、必ずログに残す
- 外部コマンドは subprocess の引数リスト形式で、shell=True は使わない
- GUI 配布ビルド（PyInstaller --windowed 等）では stdout/stderr が None。print 禁止、logging を使う
- 秘密情報（APIキー・パスワード）をコードやコミットに含めない。環境変数か Secret Manager を使う

## やってはいけないこと
- ユーザーの業務ファイル（PDF・Office・Drive上の原本）を変更・移動・削除すること
- Google Drive（G:\マイドライブ）配下で git やビルドを実行すること
